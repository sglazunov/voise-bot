# Эталонный тест качества протоколов (Д16)

Меряет качество протокола не «на глаз», а метрикой — гоняется **перед каждым
релизом** и при любой правке промпта / смене модели.

## Как добавить эталонную встречу

Каталог `cases/<имя-встречи>/` с файлами:

| Файл | Что это |
|---|---|
| `transcript.txt` | таймкодированная расшифровка встречи (как выдаёт система: `[мм:сс] реплика`, с именами спикеров, если были) |
| `notes.txt` | *(опционально)* живые заметки участника — подаются как `user_notes` |
| `reference.json` | эталонный протокол — заметки коллег + ручная выверка |
| `meta.json` | *(опционально)* `{"demo": true}` — демо-кейс, не реальная встреча |

Формат `reference.json`:

```json
{
  "tasks":      [{"task": "что сделать", "owner": "Имя или null"}],
  "done_tasks": [{"task": "что сделано", "owner": "Имя или null"}],
  "decisions":  ["что решили", "..."],
  "topics":     ["тема 1 (короткое название сути)", "..."]
}
```

Правила выверки эталона:
- в `tasks` — ВСЕ задачи, которые реально прозвучали (включая мелкие);
- `owner` только если на встрече это было сказано явно; иначе `null`;
- `topics` — все содержательные темы в хронологическом порядке.

## Запуск

```bash
# в контейнере (нужен доступ к LLM — Ollama на хосте или ключи):
docker cp tests linux-voise:/tmp/eval
docker compose exec -T app sh -c "chown -R app /tmp/eval && cd /tmp/eval/.. \
  && PYTHONPATH=/app gosu app python /tmp/eval/eval/run_eval.py --provider ollama"

# либо прямо из репозитория при локальном питоне с зависимостями:
python tests/eval/run_eval.py --provider ollama
```

Ключи: `--provider` (движок протокола), `--cases имя1,имя2` (подмножество),
`--no-verify` (без grounding-прохода), `--strict` (ненулевой код выхода при
провале порогов — для CI).

## Метрики и пороги релиза

- **task recall ≥ 0.90** — доля эталонных задач, найденных протоколом;
- **owner accuracy ≥ 0.95** — среди найденных задач ответственный совпадает
  (пустой/«—» считается «не назначен» и обязан совпадать с эталонным null);
- task precision, decisions recall, topics coverage — справочно.

Каждый прогон дописывает строку в `history.jsonl` (время, git-коммит, движок,
метрики по кейсам и сводные) — история изменения качества видна по файлу.
