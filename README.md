# linux-voise

Сервис **распознавания речи** и **сборки протоколов встреч** (Телемост) для Linux.
Разворачивается одной командой через **Docker Compose** — одинаково локально и на
сервере. Приватный: доступ только по логину/паролю, данные и токены каждого
пользователя изолированы и зашифрованы.

**Что умеет:**
- распознавание речи из аудио/видео (faster-whisper, локально) → TXT / SRT / JSON;
- протокол встречи в **Word (.docx)** через LLM (Ollama локально или Groq / GigaChat /
  YandexGPT / Gemini / Claude по ключу — с выбором тарифа модели);
- OCR текста с экрана (слайды/код на видео);
- интеграция с **Weeek** и выгрузка записей в **облако** (Я.Диск / Google Drive / локально);
- **бот-рекордер Телемоста** — Chromium заходит на встречу в виртуальном дисплее
  (Xvfb) и пишет экран + звук (ffmpeg x11grab + PulseAudio), без звука от самого бота.

Аудио/видео никуда не уходят, кроме случаев, когда вы сами выбираете облако для
записей или облачный LLM для протокола.

---

## Требования

- **Linux** (Ubuntu 22.04+ или любой дистрибутив с Docker). Проект рассчитан
  только на Linux — разворачивается на сервере/виртуальной машине.
- **Docker** + **Docker Compose v2** (`docker compose version`).
- ОЗУ: ~2 ГБ для модели `small`; **+1–2 ГБ** для бота (Chromium+Xvfb). Комфортно от
  **4 ГБ**. Ollama на сервер не ставится (подключается снаружи) — под неё память
  на этом сервере не нужна.
- Первая сборка образа — несколько минут (ставится ffmpeg, tesseract, Chromium).

Установка Docker на чистом Ubuntu:
```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker "$USER"     # затем перелогиньтесь (или newgrp docker)
```

## Запуск локально

```bash
git clone https://github.com/sglazunov/linux-voise.git
cd linux-voise
cp .env.example .env                # можно оставить как есть для локального теста
docker compose up -d --build
```

Откройте **http://localhost:8000** → страница входа. Зарегистрируйте первый аккаунт
(он станет администратором, код не нужен — см. «Аккаунты»).

- Логи: `docker compose logs -f app`
- Остановить: `docker compose down`
- Проверка: `curl http://localhost:8000/healthz`

## Раскатка на сервере

1. Поставьте Docker (см. выше) и склонируйте репозиторий на сервер.
2. Создайте `.env` и задайте **свой** ключ шифрования секретов:
   ```bash
   cp .env.example .env
   sed -i "s/^VTX_SECRET_KEY=.*/VTX_SECRET_KEY=$(openssl rand -hex 32)/" .env
   ```
3. Запустите:
   ```bash
   docker compose up -d --build
   ```
4. Откройте порт в firewall / Security Group ВМ:
   ```bash
   sudo ufw allow 8000/tcp
   ```
5. Зайдите на `http://<IP-сервера>:8000`, зарегистрируйте админа.

Контейнер поднимается с `restart: unless-stopped` — сам стартует после перезагрузки
сервера. Данные (загрузки, результаты, записи, настройки/токены, аккаунты) лежат в
`./data` на хосте и переживают пересоздание контейнера — **бэкапьте эту папку**.

> Для публичного домена дальше нужен HTTPS-прокси — см. «Домен и HTTPS».

## Аккаунты и вход

- Весь сайт закрыт логином. **Первый зарегистрированный аккаунт = основатель
  сервера** (только ему доступны серверные операции: установки, серверный HF-токен).
- Модель — **команды**: регистрация без кода создаёт СВОЁ пустое рабочее
  пространство (вы — его админ); регистрация с **кодом приглашения** админа
  (виден у него в «Профиле», меняется раз в сутки) подключает к его команде —
  общие настройки, токены и ключи.
- ⚠ **Регистрация всегда открыта**: любой, кто знает адрес, может создать себе
  отдельную команду (чужих данных он не увидит). Если это неприемлемо — закройте
  доступ на уровне прокси/VPN; переключателя «запретить новые команды» в
  приложении пока нет.
- Пароли хранятся как PBKDF2-хеши; токены Weeek/облаков — зашифрованы **отдельным
  ключом под каждый логин** (выводится из `VTX_SECRET_KEY`). Один пользователь не
  видит данные и секреты другого.
- Подробнее и тест-кейсы — [docs/БЕЗОПАСНОСТЬ.md](docs/БЕЗОПАСНОСТЬ.md).

> **Важно:** задайте свой `VTX_SECRET_KEY` до первого сохранения токенов и держите
> его вне git. Если он пустой — ключ генерируется в `data/secret.key`.

## Протокол встречи (LLM)

Распознавание работает без ключей; для **протокола** нужен движок. На сервер Ollama
**не ставится** — её нужно **подключить снаружи** (или использовать облако по ключу).

**A. Ollama — бесплатно, локально, но ВНЕШНЯЯ (у Ollama нет API-ключа):**
Поставьте её на этой же машине (на хосте, вне Docker) или на отдельном сервере:
```bash
curl -fsSL https://ollama.com/install.sh | sh
OLLAMA_HOST=0.0.0.0 ollama serve        # чтобы принимала подключения из контейнера
ollama pull qwen2.5:7b                   # модель для протокола (~4.7 ГБ)
```
Затем в `.env` приложения укажите её адрес:
```
OLLAMA_URL=http://host.docker.internal:11434   # Ollama на ЭТОЙ машине (хост)
# OLLAMA_URL=http://192.168.1.50:11434          # Ollama на другом сервере
```
и `docker compose up -d`. (По умолчанию `OLLAMA_URL` уже указывает на хост — если
Ollama там, можно ничего не менять.)

**B. Облако по ключу:** впишите в `.env` `GROQ_API_KEY` (бесплатный тариф),
`ANTHROPIC_API_KEY`, `GEMINI_API_KEY`, `GIGACHAT_AUTH_KEY`, `YANDEX_API_KEY`+
`YANDEX_FOLDER_ID` — и `docker compose up -d`. В интерфейсе у каждого провайдера
можно выбрать **тариф/мощность модели**.

## Бот-рекордер Телемоста

Включён при `VTX_RECORDER_ENABLED=1` (по умолчанию). При старте `docker/run.sh` поднимает:
- **Xvfb** — виртуальный экран `:99` (`VTX_SCREEN_RES`), Chromium открывается на весь экран;
- **PulseAudio** + **null-sink `meet0…meetN`** (по одному на слот записи) как
  устройство вывода браузера — ffmpeg пишет его монитор `meet0.monitor`.
  Создаётся при старте, настраивать ничего не нужно.

Бот заходит **с выключенными микрофоном и камерой** и ничего не транслирует.
Настройки (токен Weeek, облако, режим входа, какие встречи писать) — на странице
**`/automation`**; проверка — кнопки «Тест записи» и «Проверить звук».

Чтобы гонять **без бота** (только распознавание/протокол) — `VTX_RECORDER_ENABLED=0`.

## Настройки (`.env`)

| Переменная | По умолч. | Назначение |
|---|---|---|
| `APP_PORT` | 8000 | внешний порт |
| `VTX_MODEL` | small | модель Whisper: small / medium / large-v3 |
| `VTX_CPU_THREADS` | 4 | число потоков CPU |
| `VTX_BEAM_SIZE` | 5 | качество распознавания (1 = быстрее) |
| `VTX_LANGUAGE` | ru | язык по умолчанию |
| `GROQ_API_KEY` / `ANTHROPIC_API_KEY` / … | — | облачные LLM для протокола |
| `VTX_DIARIZATION` | 0 | «кто говорил» (нужен пересбор образа с pyannote+torch) |
| `VTX_RECORDER_ENABLED` | 1 | бот-рекордер (Xvfb+Pulse); 0 = только распознавание |
| `VTX_SCREEN_RES` | 1920x1080x24 | размер виртуального экрана бота |
| `VTX_PULSE_MONITOR` | meet.monitor | PulseAudio-источник звука встречи |
| `VTX_SECRET_KEY` | — | **ключ шифрования секретов** (задайте свой на сервере!) |
| `VTX_REGISTRATION_CODE` | — | код приглашения для регистрации после админа |
| `VTX_HTTPS` | 0 | `1` = cookie с флагом Secure (за HTTPS-прокси) |
| `VTX_SESSION_TTL_HOURS` | 168 | срок жизни сессии |
| `TZ` | Europe/Moscow | часовой пояс |

После правки `.env`: `docker compose up -d` (пересоздаст контейнер с новыми env).

## Обновление и обслуживание

```bash
git pull                      # забрать изменения
docker compose up -d --build  # пересобрать и перезапустить
```
- Логи: `docker compose logs -f app`
- Бэкап: сохраняйте папку `./data` (там всё состояние).
- Модель на лету: `VTX_MODEL=medium docker compose up -d` (первый запрос докачает её).

## Домен и HTTPS (следующий шаг)

Сейчас сервис отдаётся по `http://IP:8000`. Для домена:
1. Направьте A-запись домена на IP сервера.
2. Поставьте reverse-proxy (nginx/Caddy) перед приложением, выпустите сертификат
   Let's Encrypt и задайте `VTX_HTTPS=1`. Готовый конфиг добавим отдельным шагом.

## Решение проблем

- **`docker compose` не найден** — нужен Compose v2 (плагин); на старых системах
  команда `docker-compose` (с дефисом).
- **Долго «Загрузка модели…»** на первом запросе — модель Whisper качается один раз,
  потом кэшируется в `./data`.
- **Протокол не собирается** — не выбран движок: поднимите Ollama (`--profile local-ai`
  + `scripts/setup-ollama.sh`) или задайте облачный ключ.
- **Нет доступа снаружи** — откройте порт: `sudo ufw allow 8000/tcp`.
- **OOM / мало памяти** — `VTX_MODEL=small`, без диаризации, без Ollama на маленькой ВМ.
- **Бот не заходит / запись пустая** — проверьте `/automation` → «Тест записи» и
  «Проверить звук»; вёрстка Телемоста иногда меняется (селекторы в
  `app/automation/recorder/browser.py`).

## Без Docker (запасной путь)

В репозитории есть `deploy.sh` (venv + ffmpeg) и `voicetx.service` (systemd) — для
запуска ядра без контейнеров. Docker — рекомендуемый путь; бот-рекордеру при этом
всё равно нужны Xvfb + PulseAudio на хосте.
