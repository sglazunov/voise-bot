# linux-voise

Linux-сборка сервиса **распознавания речи** и **сборки протоколов встреч**
(перенос Windows-приложения Voice Transcriber). Разворачивается одной командой
через **Docker Compose** — одинаково локально и на виртуальной машине.

Включает: распознавание речи (видео/аудио), протокол встречи (Word), OCR текста
с экрана, интеграцию с **Weeek**, выгрузку в **облако** (Я.Диск / Google Drive /
локально) и **бот-рекордер Телемоста** — Chromium заходит на встречу внутри
виртуального дисплея (Xvfb) и пишет экран + звук (x11grab + PulseAudio).

Всё работает на вашем сервере: аудио/видео никуда не уходят, кроме случаев, когда
вы сами выбираете облако для записей или облачный LLM для протокола.

---

## Требования

- Linux-сервер (Ubuntu 22.04+ или любой с Docker).
- **Docker** + **Docker Compose v2** (`docker compose version`).
- ОЗУ: ~2 ГБ для `small`-модели; **+ ~1–2 ГБ для бота** (Chromium+Xvfb);
  для локального ИИ-протокола Ollama — ещё ~5–6 ГБ. Итого комфортно от 4 ГБ.
- Образ с ботом весит больше (Chromium ~400 МБ) — первая сборка идёт несколько минут.

Установка Docker (Ubuntu):
```bash
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker "$USER"   # затем перелогиньтесь
```

## Быстрый старт

```bash
git clone https://github.com/sglazunov/linux-voise.git
cd linux-voise
cp .env.example .env            # при желании отредактируйте
docker compose up -d --build
```

Откройте **http://<IP-сервера>:8000** (локально — http://localhost:8000).

Проверка здоровья: `curl http://localhost:8000/healthz`.

Логи: `docker compose logs -f app`  ·  Стоп: `docker compose down`.

Данные (загрузки, результаты, настройки/токены) хранятся в `./data` на хосте —
переживают пересоздание контейнера.

## Протокол встречи (LLM)

Для сборки протокола нужен один из движков. Распознавание работает и без них.

**Вариант A — локально и бесплатно (Ollama):**
```bash
docker compose --profile local-ai up -d --build   # поднимет сервис ollama
bash scripts/setup-ollama.sh                       # один раз: скачает модель ~4.7 ГБ
```
Приложение обращается к Ollama по адресу `http://ollama:11434` автоматически.

**Вариант B — облако по ключу:** впишите в `.env` `GROQ_API_KEY` (бесплатный тариф),
`ANTHROPIC_API_KEY`, `GEMINI_API_KEY` и т.п. и пересоздайте: `docker compose up -d`.

## Настройки (`.env`)

| Переменная | По умолч. | Назначение |
|---|---|---|
| `APP_PORT` | 8000 | внешний порт |
| `VTX_MODEL` | small | модель Whisper: small / medium / large-v3 |
| `VTX_CPU_THREADS` | 4 | число потоков CPU |
| `VTX_BEAM_SIZE` | 5 | качество (1 = быстрее) |
| `VTX_LANGUAGE` | ru | язык по умолчанию |
| `GROQ_API_KEY` / `ANTHROPIC_API_KEY` / … | — | облачные LLM для протокола |
| `VTX_DIARIZATION` | 0 | «кто говорил» (нужен пересбор образа с pyannote+torch) |
| `VTX_RECORDER_ENABLED` | 1 | бот-рекордер Телемоста (Xvfb+Pulse); 0 = только распознавание |
| `VTX_SCREEN_RES` | 1920x1080x24 | размер виртуального экрана для бота |
| `VTX_PULSE_MONITOR` | meet.monitor | PulseAudio-источник звука встречи |
| `TZ` | Europe/Moscow | часовой пояс |

После правки `.env`: `docker compose up -d` (пересоздаст контейнер с новыми env).

Сменить модель на лету: `VTX_MODEL=medium docker compose up -d` (первый запрос
скачает модель — несколько минут).

## Домен и HTTPS (следующий шаг)

Сейчас сервис отдаётся по `http://IP:8000`. Чтобы повесить домен:
1. Направьте A-запись домена на IP виртуальной машины.
2. Поставьте reverse-proxy (nginx/Caddy) перед приложением и выпустите сертификат
   Let's Encrypt. Готовый конфиг nginx + certbot добавим отдельным шагом — скажите,
   когда домен будет готов.

## Бот-рекордер Телемоста (Linux)

Включается переменной `VTX_RECORDER_ENABLED=1` (по умолчанию в `.env.example`).
При старте контейнера `docker/run.sh` поднимает:
- **Xvfb** — виртуальный дисплей `:99` (размер `VTX_SCREEN_RES`, по умолч. 1920×1080),
  в нём Chromium открывается развёрнутым на весь экран;
- **PulseAudio** + **null-sink `meet`**, сделанный устройством вывода по умолчанию —
  браузер играет звук встречи в него, а ffmpeg пишет его монитор `meet.monitor`
  (это Linux-замена VB-CABLE — настраивать ничего не нужно, всё автоматически).

Захват: `ffmpeg -f x11grab -i :99 -f pulse -i meet.monitor … out.mp4`. Бот заходит
**с выключенными микрофоном и камерой** (использует fake-устройства Chromium —
в встречу от него ничего не идёт). Всё настраивается на странице **`/automation`**
(токен Weeek, облако, режим входа), настройки хранятся в `/data`.

Chromium ставится в образ (`playwright install --with-deps chromium`), работает без
sandbox (`--no-sandbox`), контейнеру даётся `shm_size: 1gb`.

> Бот — самая хрупкая часть (Телемост меняет вёрстку, нужен реальный звонок для
> теста). Проверьте на странице `/automation` → «Тест записи» и «Проверить звук»
> (должно быть «✓ звук есть» после того, как в звонке кто-то говорит).
> Чтобы запускать **без бота** (только распознавание/протокол) — поставьте
> `VTX_RECORDER_ENABLED=0`.

## Решение проблем

- **`docker compose` не находит команду** — нужен Compose v2 (плагин);
  на старых системах команда `docker-compose` (с дефисом).
- **Первый запрос долго «Загрузка модели…»** — модель Whisper качается один раз
  (large-v3 ~3 ГБ); потом кэшируется в `./data`.
- **Протокол не собирается** — не выбран движок: поднимите Ollama
  (`--profile local-ai` + `scripts/setup-ollama.sh`) или задайте облачный ключ в `.env`.
- **Нет доступа снаружи** — откройте порт в firewall/Security Group ВМ
  (`sudo ufw allow 8000/tcp`).
- **Мало памяти / OOM** — используйте `VTX_MODEL=small`, не включайте диаризацию,
  не запускайте Ollama на маленькой ВМ.

## Альтернатива без Docker (native)

В репозитории есть `deploy.sh` (venv + ffmpeg) и `voicetx.service` (systemd) для
запуска без контейнеров. Docker — рекомендуемый путь; native оставлен как запасной.
