# Lock зависимостей образа: ТОЧНЫЕ версии всего, что ставит pip, включая
# транзитивные. Dockerfile ставит requirements.txt с `-c requirements.lock.txt`:
# пересборка образа (в том числе после правки одной строки Dockerfile, которая
# сбрасывает кэш слоёв) берёт ровно эти версии, а не свежие из открытых
# диапазонов requirements.txt. Без lock так случился PyAV 19 (05.10): пересборка
# подтянула новую транзитивную версию, и распознавание легло. CI ставит тот же
# lock — тесты идут на тех же версиях, что в образе.
#
# Платформа — образ: Linux x86_64, CPython 3.12. Обновлять осознанно:
#  - правка requirements.txt -> пересобрать lock и прогнать тесты;
#  - из собранного и проверенного образа (авторитетно, без DIARIZATION):
#      docker compose run --rm --no-deps --entrypoint pip app freeze > requirements.lock.txt
#    (заголовок верните; строки torch/pyannote, если были, уберите);
#  - без сервера — резолвом pip под Linux (маркеры платформы при этом считаются
#    по машине, где запускают: на Windows добавить uvloop, убрать colorama):
#      pip install --dry-run --ignore-installed --report r.json --only-binary=:all: \
#        --platform manylinux_2_28_x86_64 --platform manylinux2014_x86_64 \
#        --python-version 3.12 --implementation cp --abi cp312 -r requirements.txt
# Тест tests/test_requirements_pins.py сверяет lock с requirements.txt.
