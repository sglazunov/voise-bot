# ТЗ: раскладка видео и протоколов по папкам встреч

Дата: 28.10.2026. Статус: **реализовано** (ветка `claude/repo-sync-meeting-protocols-x0wb98`).

## 1. Проблема

Сейчас всё лежит плоско в двух папках облака:

```
disk:/Телемост-записи/     ← видео ВСЕХ встреч вперемешку
disk:/Телемост-протоколы/  ← протоколы ВСЕХ встреч вперемешку
```

Чтобы найти протоколы одной серии («Встреча с ОО», «Виртуальный помощник»),
приходится листать сотни файлов, а видео и протокол одной встречи лежат в
разных папках.

## 2. Что нужно (слова заказчика)

> Есть встреча с ОО — папка так и называется, туда кладутся все протоколы по
> этой встрече. Встреча по виртуальному помощнику — своя папка. Разовые
> встречи — в отдельную папку. Видео встречи и протокол по ней кладутся в
> соответствующую папку, с датой видео и датой протокола. И так по всем.

## 3. Целевая структура

```
disk:/Телемост-записи/                       ← «Папка встреч» (бывшая «Папка для записи»)
├── Встреча с ОО/
│   ├── 20.10.2026, 10:00. - Встреча с ОО.mp4
│   ├── 20.10.2026, 10:00. - Встреча с ОО - протокол.docx
│   ├── 27.10.2026, 10:00. - Встреча с ОО.mp4
│   └── 27.10.2026, 10:00. - Встреча с ОО - протокол.docx
├── Виртуальный помощник/
│   └── …
└── Разовые встречи/
    ├── 22.10.2026, 15:00. - Созвон с юристом.mp4
    └── 22.10.2026, 15:00. - Созвон с юристом - протокол.docx
```

## 4. Требования

### Папки

- **П1.** Видео и протокол одной встречи кладутся в ОДНУ папку — папку её
  серии. Отдельная «Папка для протокола» при включённой раскладке не
  используется.
- **П2.** Папки серий создаются внутри папки записей выбранного облака
  (Яндекс.Диск — «Папка для записи», Google Drive — папка записей, локальный
  диск — `local_dir`). Папка серии создаётся автоматически при первой
  выгрузке.
- **П3.** Имя папки серии — название серии без даты и времени, как в
  Weeek («Встреча с ОО»). Знаки `\ / : * ? " < > |` заменяются пробелом,
  точки и пробелы по краям срезаются, длина — до 80 символов.
- **П4.** Встречи, которые не являются серией, кладутся в общую папку
  «Разовые встречи» (имя задаётся в настройках).
- **П5.** Имена файлов не меняются: они уже начинаются с даты и времени
  встречи («20.10.2026, 10:00. - …mp4», «… - протокол.docx»).

### Что считается серией

- **С1.** Серия — встреча, у которой есть карточка, настроенная человеком
  (контекст, тип протокола, приоритет, проект Weeek или имя папки), ЛИБО
  встреча с тем же названием уже была в ДРУГОЙ день.
- **С2.** Первая встреча с новым названием — разовая (в «Разовые встречи»).
  Видео и протокол одной встречи (один день) — всегда одно проведение.
- **С3.** Когда у названия появляется вторая встреча в другой день, оно
  становится серией: заводится папка, а видео и протокол первой встречи
  **переезжают** из «Разовых встреч» в папку серии.
- **С4.** Встреча «по ссылке» и ручная загрузка файла раскладываются по тем
  же правилам — по названию.
- **С5.** Решение человека на карточке серии («Контекст для ИИ» →
  «Повторяющиеся встречи» → «Папка в облаке») главнее автоматики:
  - «авто» — правила С1–С3;
  - «своя папка серии сразу» — папка с первой встречи;
  - «в «Разовые встречи»» — всегда в общую папку, даже если повторяется;
  - «Имя папки» — своё имя вместо названия серии.

### Переезд из «Разовых»

- **Р1.** Каждый файл, положенный в «Разовые встречи», запоминается у серии
  его названия (путь, облако, день). Держится до 20 файлов на серию.
- **Р2.** Переезд выполняется при следующей выгрузке встречи этой серии
  (видео или протокола), до неё.
- **Р3.** ⚠️ Ссылки на файлы уже стоят в задачах Weeek. На Яндекс.Диске
  публичная ссылка сверяется до и после перемещения; если она сменилась или
  пропала — файл **возвращается на место**, переезд считается
  несостоявшимся, ссылка в Weeek продолжает работать.
- **Р4.** Сетевые сбои повторяются (до трёх попыток на следующих
  выгрузках); файл, которого уже нет, или конфликт имён — снимается из
  очереди без повторов.
- **Р5.** Переезд не мешает выгрузке: любой его сбой пишется в лог и
  только.

### Настройки (страница «Облако»)

- **Н1.** «Раскладывать по папкам встреч» — включено по умолчанию
  (`folders_by_series`). Выключено — всё как раньше, плоско.
- **Н2.** «Папка для разовых встреч» — по умолчанию «Разовые встречи»
  (`oneoff_folder`).
- **Н3.** При включённой раскладке поле «Папка для протокола» показывается
  неактивным с пояснением, что не используется.

## 5. Облака

| | Яндекс.Диск | Google Drive | Локальный диск |
|---|---|---|---|
| Подпапка | путь `<папка записей>/<серия>` | дочерняя папка (ищется/создаётся по имени) | подкаталог |
| Переезд | `POST /resources/move` + сверка ссылки | смена родителя (`addParents/removeParents`) — ссылка = id файла, не меняется | переименование файла |

Ограничение Google Drive: с правами `drive.file` бот видит только созданное
им самим — папку с тем же именем, заведённую руками, он не найдёт и создаст
рядом свою. Если создать подпапку не удалось — файл ложится в общую папку с
пояснением.

## 6. Что не входит

- **Старые файлы не переносятся.** Всё, что уже лежит в
  «Телемост-записи» и «Телемост-протоколы», остаётся на месте; раскладка
  действует с первой выгрузки после обновления. Разовый перенос архива
  возможен отдельным скриптом — только с проверкой, что ссылки в Weeek не
  ломаются.
- **Переименование серии или смена «Имени папки»** не перевозит уже
  выгруженные файлы: новые ложатся в новую папку.
- Из «Разовых» в серию переезжает только то, что выгружено после
  обновления (до него пути файлов не запоминались).

## 7. Не проверено на живом облаке

Сохраняется ли публичная ссылка Яндекс.Диска при перемещении файла — из
среды разработки не проверить (сервис закрыт). Код рассчитан на оба исхода
(Р3): если ссылка сохраняется — файлы переезжают; если нет — остаются в
«Разовых» с рабочей ссылкой, а в логе `vtx.folders` появится причина.
Проверка после раскатки: провести вторую встречу с названием, у которого
первая лежит в «Разовых», и посмотреть лог карточки — строка «…стала
серией — N файл(ов) прежних встреч перенесено».

## 8. Приёмка

1. Новая встреча «Созвон с юристом» → видео и протокол в «Разовые встречи».
2. Встреча с карточкой серии «Встреча с ОО» (есть контекст) → видео и
   протокол в папке «Встреча с ОО» с первой же встречи.
3. «Виртуальный помощник» 20.10 — в «Разовые»; 27.10 — появилась папка
   «Виртуальный помощник», в ней обе встречи (видео + протокол каждой).
4. На карточке серии выбрано «в «Разовые встречи»» → файлы серии идут в
   общую папку.
5. «Раскладывать по папкам встреч» выключено → всё как раньше.
6. Ссылки в полях Weeek «Видео встречи» и «Протокол встречи» открываются
   после любого переезда.

## 9. Где в коде

- `app/cloud_folders.py` — правила (`resolve`), запоминание разовых
  (`placed`), переезд (`adopt`), имя папки (`safe_name`);
- `app/automation/clouds/__init__.py` — `upload(..., subfolder=)`,
  `move_to_sibling`; `yandex_disk.move`, `gdrive.child_folder`,
  `gdrive.move_to_sibling`;
- `app/meeting_series.py` — поля карточки `folder_mode`, `folder`,
  `oneoff_files`;
- выгрузка: `jobs._deliver_protocol` (протокол),
  `scheduler._meeting_place` → `_run`, `_late_upload`, `_finalize_orphan`
  (видео);
- интерфейс: «Облако» → «Раскладка по встречам»; «Контекст для ИИ» →
  карточка серии → «Папка в облаке».
- Тесты — `tests/test_cloud_folders.py`.
