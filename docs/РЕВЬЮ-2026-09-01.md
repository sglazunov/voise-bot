## 3. Что закрыто (код в ветке `claude/repo-sync-meeting-protocols-x0wb98`)

### Протокол
- **Контекст перед текстом в каждом запросе.** Блоки участников, постоянного
  контекста и серии раньше дописывались в конец расшифровки: на длинной встрече
  при нарезке они попадали только в последний фрагмент, а сведение их не видело
  вовсе. Теперь `analyze_transcript(..., context=)`.
- **Память серии встреч** (`app/meeting_series.py`, API `/api/series`,
  страница «Контекст для ИИ» → «Повторяющиеся встречи»): карточка серии
  (проект, участники и роли, цели, термины), закреплённый тип протокола,
  приоритет «обычный / срочный / только запись», проект Weeek для задач;
  автоматическая память о прошлой встрече серии (решения, открытые задачи)
  уходит в промпт. Черновики карточек для 14 серий — `docs/series-seed.json`,
  импорт — `scripts/import_series_context.py`.
- **Оборванный ответ модели — ошибка, а не пустой протокол** (`TruncatedAnswer`
  + повтор с просьбой сократить описания; ответ без единого поля схемы не
  принимается).
- **Честная проверка цитат:** пачки по 15 пунктов; стемминг окончаний; метки
  говорящих вырезаются перед сравнением; «починенная» моделью опечатка
  распознавания принимается как ≈; при сбое проверки пункты остаются
  непроверенными (Word и интерфейс не красят их как опровергнутые).
- **Дедуп заметок** не склеивает «на синий/на красный», «Ивану/Марии», разные
  ответственные.
- **Структура «сначала решения и задачи»:** порядок генерации и разделов Word
  — участники → кратко → решения → задачи (с колонкой «Срок») → мелкие →
  сделано → выводы и открытые вопросы («Открыто:», «Риск:») → темы (5-9
  предложений) → мысли. Интерфейс — в том же порядке, темы свёрнуты.
- **Типы встреч:** добавлены «встреча с заказчиком», «управленческая»,
  «ревью макетов»; автоопределение по началу слова («редизайн» ≠ дизайн);
  закрепление типа в карточке серии.
- **Контекст проектов** подбирается по целым словам, псевдонимы через «|»
  («ОД | Обычное дело»); «ОД» больше не совпадает с «прОДукт».
- **Участники:** подписи плиток сводятся к известным именам из контекста и
  карточки серии («ЗЖКИРИЛЛ БУБНОВ» → «Кирилл Бубнов», «Mapua H» → «Мария Н»).
- **Текст с экрана:** секреты маскируются до модели и до записи на диск
  (`app/redact.py`); объём ограничен 12 000 символов и 40 % речи; при
  пересборке OCR подмешивается, как в первом прогоне.

### Задачи → Weeek
- `app/weeek_tasks.py`: черновики из протокола с основанием-цитатой, исполнителем
  из воркспейса (маппинг команды → полное имя → уникальное имя как «нестрогое»),
  сроком из речи («до пятницы» → дата от даты встречи). Идемпотентность по ключу
  и отпечатку текста. Блок «Задачи → в Weeek» на странице протокола, настройки
  на странице Weeek, авторежим выключен по умолчанию.
- Клиент: участники, доски, колонки, создание задачи, срок отдельным PUT.
  **Формы запросов не проверены на живом API** (документация Weeek недоступна
  из среды разработки) — первый запуск делать на тестовом проекте.

### Безопасность
- Сессия входа в Яндекс изолирована по командам (была одна на процесс — чужая
  команда видела экран и могла слать клики); `goto` только на паспорт Яндекса.
- SSRF: адрес своего провайдера проверяется по DNS, а не только по IP-литералу.
- CSRF-проверка `Sec-Fetch-Site`/`Origin`, заголовок CSP, compose без пароля
  БД по умолчанию и с портом только на localhost, `task_id` Weeek валидируется.

### Weeek/планировщик
- Ночная чистка полей — только у сегодняшних встреч (разовые встречи прошлой
  недели теряли ссылки); карточка встречи не выбирается из будущего (заметки
  уезжали в следующее проведение); `Retry-After` на 429; первая страница до
  веера параллельных запросов.

### Инфраструктура
- GitHub Actions: pytest (без движка распознавания), tsc, vite build.
- Тестов: 480 (было 427).

## 4. Что осталось — бэклог для доски бота

Приоритет 1
- Пробная запись в тестовом проекте Weeek: назначение исполнителя (`userId`
  в теле или `POST /tasks/{id}/assignees`), формат `dueDate`, теги. Потом
  включать черновики для команды.
- Заполнить карточки серий (черновики в `docs/series-seed.json` — проверить
  имена, роли, термины) и импортировать.
- Замерить эффект на следующих 10–15 встречах тем же скриптом: доля задач с
  основанием, пустые протоколы, мусор в участниках.

Приоритет 2
- Потоковый режим (SSE) для провайдера `custom` и известные `context_window` /
  `max_output` для Yandex Cloud: без них «Стоп» внутри вызова не действует, а
  длинная генерация может упереться в 504.
- `_MAX_CHARS` зависит от движка: 30-минутная встреча на DeepSeek не должна
  идти через карту/сведение.
- Использовать цитаты из заметок карты в проверке (меньше вызовов, меньше ⚠).
- Классификация типа встречи вторым шагом через дешёвый вызов модели, когда по
  названию не определяется.
- Срочный протокол — вперёд очереди (сейчас «срочно» только помечает серию).
- Расширение Кирилла: задача из чата Телемоста (только при `auth_mode: profile`).

Приоритет 3 (интерфейс, доступность)
- Загрузка файла с клавиатуры (`input type=file` скрыт как `display:none`),
  `htmlFor` у полей форм, `role="listbox"` у Select, фокус-ловушка в Modal,
  `aria-live` у тостов, контраст статусных цветов в светлой теме.
- Заголовок протокола — название встречи и дата, а не имя файла; кнопка
  «Пересобрать» должна показывать, каким движком.
- Тесты слоя `app/db.py` с живым Postgres (сейчас проверяется файловая ветка).
- README/ШПАРГАЛКА: убрать `deploy.sh`, `scripts/setup-ollama.sh`, `--profile
  local-ai`, старый адрес репозитория; `numpy`, `httpx`, `pytest-timeout` — в
  requirements; `pytest.ini` — в образ.

## 6. Ревью 128 протоколов (07.07–02.09) — закрыто 02.09

Разбор трёх поколений бота (v1: 2,7 задачи на встречу, без цитат; v2: цитаты,
но 74 % задач без исполнителя; v3: правильная структура) выявил восемь
дефектов. Все восемь закрыты в коде, эффект на живых встречах ещё не замерен:

| Дефект | Что сделано |
|---|---|
| Каждый третий протокол августа — запасным движком после 429 | ожидание лимита 240/900 с вместо 90/300; откат помечается «ЧЕРНОВИК» в заголовке |
| 40 % задач без исполнителя в таблице | таблица только с ответственным; остальные — «назначьте исполнителя» |
| Обращение «Паша, можешь…» не читалось | `names.addressee`: обращение + словарь уменьшительных |
| Ложные отказы проверки; «Нет, не надо» игнорировалось; прошедшее время как задача | поиск опоры по основам слов; отказ в следующих репликах; «я добавил» → «Сделано» |
| Разделы из контекста серии («8 программистов, Asana») | второй проход по якорям: тема без опоры удаляется, с частичной — помечается |
| Шум («написать Виктору за доступом», реплики про бота) | стоп-лист + `VTX_TASK_STOPLIST` |
| Задачи прошлой встречи не сверялись | таблица «Задачи прошлой встречи: закрыта / в работе / без упоминания» |
| Таймкоды `[013:01]`, «Зояр» | нормализация таймкодов; сравнение имён без пробелов |

Контрольный замер — на следующих 10–15 встречах тем же скриптом: доля задач с
исполнителем, доля «требуют проверки», число «ЧЕРНОВИКОВ», удалённые темы в логе
(`vtx.analyze`: «Удалены темы без опоры»).
