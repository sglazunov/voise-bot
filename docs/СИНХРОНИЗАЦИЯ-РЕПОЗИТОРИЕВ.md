# Синхронизация репозиториев: SourceCraft ↔ GitHub

Проект живёт в двух репозиториях, и они должны быть одинаковыми:

| Где | Адрес | Роль |
|---|---|---|
| Яндекс SourceCraft | `ssh://git@ssh.sourcecraft.dev/organization-katserglazunov/linux-voise.git` | основной (исторически), туда смотрит боевой сервер |
| GitHub | `https://github.com/sglazunov/voise-bot` | зеркало для Claude Code на вебе, ревью и CI |

Ветка по умолчанию в обоих — `main`. Правило одно: **любой коммит уходит в оба
репозитория одной командой `git push`**. Для этого у локального `origin` делается
два push-адреса — Git сам отправит коммит в оба места.

## 1. Разовая настройка на машине разработчика (Windows, `D:\linux-voise`)

```bash
cd /d/linux-voise

# 1) Убедиться, что origin — SourceCraft (так и было)
git remote -v

# 2) Добавить GitHub ВТОРЫМ push-адресом того же origin
git remote set-url --add --push origin ssh://git@ssh.sourcecraft.dev/organization-katserglazunov/linux-voise.git
git remote set-url --add --push origin https://github.com/sglazunov/voise-bot.git

# 3) Отдельный remote только для чтения GitHub (нужен, чтобы забирать
#    ветки, которые Claude Code создаёт на GitHub)
git remote add github https://github.com/sglazunov/voise-bot.git

git remote -v
# origin  ssh://git@ssh.sourcecraft.dev/... (fetch)
# origin  ssh://git@ssh.sourcecraft.dev/... (push)
# origin  https://github.com/sglazunov/voise-bot.git (push)
# github  https://github.com/sglazunov/voise-bot.git (fetch/push)
```

> Первую команду `set-url --add --push` с адресом SourceCraft нужно выполнить
> обязательно: как только у remote появляется хотя бы один явный push-адрес,
> Git перестаёт использовать fetch-адрес для push.

Для GitHub по HTTPS нужен токен (Personal Access Token с правом `repo`) или
Git Credential Manager — на Windows он ставится вместе с Git и запросит вход
в браузере при первом push. Если удобнее SSH — замените адрес на
`git@github.com:sglazunov/voise-bot.git` и добавьте ключ в GitHub → Settings →
SSH keys.

## 2. Ежедневная работа

```bash
git pull                      # забирает из SourceCraft (fetch-адрес origin)
git fetch github              # забирает ветки с GitHub (ветки Claude Code)
# ... правки, коммит ...
git push                      # уходит и в SourceCraft, и на GitHub
```

Если `git push` упал по одному из адресов (обычно SourceCraft из-за сети —
см. раздел «Git до SourceCraft: только порт 443» в CLAUDE.md), повторите
просто `git push` ещё раз — Git пушит в каждый адрес независимо, уже
доставленное не пострадает.

## 3. Как забирать работу Claude Code с GitHub

Claude Code на вебе работает с GitHub и создаёт ветки вида
`claude/<тема>-<код>`. Чтобы они попали в SourceCraft:

```powershell
git fetch github
git checkout main
git merge github/claude/repo-sync-meeting-protocols-x0wb98   # пример
git push                       # main уходит в оба репозитория
```
(каждая строка — отдельная команда; `&&` в PowerShell не работает)

После слияния ветку на GitHub можно удалить: `git push github --delete claude/...`.

## 4. Первое выравнивание — СДЕЛАНО 01.09.2026

`main` с полной историей SourceCraft уже отправлен на GitHub (команды из
раздела 1 выполнены, `git push` доставил ветку `main` в оба репозитория).
Ветка `claude/repo-sync-meeting-protocols-x0wb98` пересажена поверх этого
`main`, поэтому её можно сливать обычным способом:

```powershell
cd D:\linux-voise
git pull
git fetch github
git merge github/claude/repo-sync-meeting-protocols-x0wb98
git push          # main → SourceCraft + GitHub
```

> На Windows команды выполняются в PowerShell или Git Bash (ярлык «Git Bash»
> ставится вместе с Git for Windows). Пути вида `/d/…` работают только в Git
> Bash; в PowerShell пишите `D:\…`. В Windows PowerShell 5.1 НЕТ оператора
> `&&` — команды вводите по одной или разделяйте `;`. WSL для этого не нужен.

## 5. Боевой сервер

Сервер забирает код по `git pull` из SourceCraft (см. `scripts/update.sh`).
Раз оба репозитория одинаковые, при проблемах с SourceCraft (порт 22/443)
сервер может тянуть с GitHub:

```bash
cd ~/bot/linux-voise
git remote add github https://github.com/sglazunov/voise-bot.git   # один раз
git pull github main && docker compose up -d --build
```

Для приватного репозитория на сервере нужен токен только на чтение
(Fine-grained PAT: Contents → Read) — его удобно положить в
`~/.git-credentials` через `git config credential.helper store`.

## 6. Что НЕЛЬЗЯ делать

- Не пушить в один репозиторий с `--force`, не перепушив так же второй:
  истории разойдутся, и следующий `git push` в один из адресов будет отвергнут.
- Не создавать ветку `main` на GitHub «из интерфейса» (кнопкой) — получится
  пустой корень, который потом не слить с историей SourceCraft.
- Не переносить сюда ничего из старого `voice-transcriber-glazunov` (см.
  предупреждение в CLAUDE.md).

## 7. Проверка, что всё синхронно

```bash
git fetch --all
git rev-parse origin/main github/main     # два одинаковых хэша = порядок
```
