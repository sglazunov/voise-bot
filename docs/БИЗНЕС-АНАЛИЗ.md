# 💼 Бизнес-анализ

Документ отвечает на вопросы: **какую проблему решаем, кому это ценно, сколько это
экономит, какие требования и риски.** Написан просто — понятно и не-технарю.

---

## 1. Проблема (боль)

Встречи отнимают время **дважды**:

1. Сначала на **самой встрече**.
2. Потом на «послевкусии»: вспомнить, законспектировать, оформить протокол,
   поставить задачи, никого не забыть.

Что идёт не так на практике:

- Протоколы **не пишут вовсе** — «и так всё помним» (а через неделю не помнят).
- Пишут, но **долго и криво** — теряются детали, цифры, сроки.
- **Путаница с ответственными** — «кто это должен был сделать?».
- Записи встреч лежат **мёртвым грузом** — по ним никто не возвращается.
- Ручная рутина «зайти на встречу → записать → расшифровать → оформить» съедает
  время дорогих сотрудников.

> **Суть боли:** ценная информация со встреч теряется, а её «спасение» стоит
> ручного труда.

---

## 2. Решение (ценностное предложение)

Сервис **автоматически** превращает встречу в готовый протокол и раскладывает
результаты по местам, максимально **без участия человека**.

| Боль | Как закрывается |
|---|---|
| Не вести конспект руками | распознавание речи → полный текст (TXT/SRT/JSON) |
| Быстро понять «что решили / кто должен» | ИИ собирает протокол: решения, задачи, **ответственные** |
| Путаница «кто говорил / чья задача» | имя говорящего **читается прямо с видео** (подсветка Телемоста) |
| Правильные имена и термины | подсказка терминов + глоссарий замен |
| Учесть показанное на экране | OCR слайдов/кода с видео |
| Рутина «зайти-записать-расшифровать» | **бот сам** пишет встречу из задачи Weeek и гонит по конвейеру |
| Поделиться итогом | экспорт в **Word**, ссылка кладётся в задачу Weeek |
| Конфиденциальность | распознавание и (опц.) ИИ — **локально**, без облака |

**Ключевой принцип:** *локально по умолчанию; наружу уходит только то, что
пользователь явно разрешил.*

---

## 3. Заинтересованные стороны (стейкхолдеры)

| Кто | Что хочет | Что получает |
|---|---|---|
| **Руководитель / тимлид** | видеть итоги встреч и задачи без ручной возни | готовый протокол с задачами и ответственными |
| **Участник встречи** | не отвлекаться на конспект | можно просто участвовать — запишет робот |
| **Проектный менеджер** | связать встречи с задачами в трекере | ссылка на запись/протокол прямо в задаче Weeek |
| **Администратор/DevOps** | развернуть и забыть | один Docker-compose, работает 24/7 |
| **Служба безопасности** | данные не утекают | локальная обработка, шифрование, изоляция по пользователям |
| **Владелец бизнеса** | экономия времени команды | меньше ручного труда, ничего не теряется |

---

## 4. Бизнес-цели и польза

- **Экономия времени.** Убираем ручное конспектирование и оформление протоколов.
- **Ничего не теряется.** Каждая встреча превращается в текст + структурированный
  протокол, к которому можно вернуться.
- **Прозрачность ответственности.** Задачи и ответственные фиксируются, а имена
  берутся с видео — меньше споров «кто должен был».
- **Конфиденциальность как преимущество.** Можно работать полностью локально —
  подходит для чувствительных встреч.
- **Низкий порог входа.** Разворачивается одной командой, без дорогого железа
  (работает на обычном CPU, без видеокарты).

### Ориентировочная выгода (пример расчёта)

> Допустим, в компании 20 встреч в неделю, и оформление протокола вручную занимает
> ~20 минут каждый. Это **≈6,5 часов в неделю** ручного труда. Сервис сводит это
> почти к нулю: человек лишь при желании проверяет готовый документ. Цифры зависят
> от компании — но порядок экономии именно такой.

## 5. Границы проекта (scope)

**Входит в проект:**

- Распознавание речи из аудио/видео (локально, без интернета).
- Сборка протокола ИИ (локальный Ollama или облачные движки по ключу).
- Определение говорящего по видео Телемоста + опц. диаризация по звуку.
- OCR текста с экрана (слайды/код).
- Бот-запись встреч Телемоста и весь конвейер вокруг неё.
- Интеграция с Weeek (источник встреч + запись ссылок в поля) и с облаками
  (Яндекс.Диск / Google Drive / локальный диск).
- Веб-интерфейс с авторизацией и изоляцией пользователей.

**Не входит (осознанно):**

- Официальная интеграция с Телемостом по API (у него **нет** публичного API для
  ботов — поэтому запись через браузер).
- Мобильные приложения.
- Аналитика/дашборды по встречам (только протоколы и файлы).
- Автоматическая простановка задач в трекере из протокола (пока — только ссылка и
  комментарий; простановка задач возможна как развитие).

## 6. Бизнес-требования (верхнеуровневые)

| № | Требование | Приоритет |
|---|---|---|
| BR-1 | Превращать запись встречи в текст без ручного труда | Must |
| BR-2 | Формировать понятный протокол с решениями/задачами/ответственными | Must |
| BR-3 | Работать локально и приватно по умолчанию | Must |
| BR-4 | Автоматически записывать встречи из задач Weeek | Must |
| BR-5 | Класть результаты в облако и ссылку — в задачу | Should |
| BR-6 | Правильно определять, кто говорил (по видео) | Should |
| BR-7 | Управляться людьми без глубоких IT-навыков (простой веб-UI) | Should |
| BR-8 | Разворачиваться одной командой и работать 24/7 | Must |
| BR-9 | Не терять доступы/настройки при перезапуске сервера | Must |

---

## 7. Правила и договорённости (бизнес-логика)

- **Запись всегда, распознавание и протокол — по флагам.** Даже если распознавание
  выключено, запись и выгрузка в облако выполняются.
- **Кем управляется запись встречи (важное правило приоритета):**
  1. Ручной выбор в интерфейсе (записывать / не записывать) — **главнее всего**.
  2. Галочка-поле в Weeek «Запись встречи» — включена → пишем, выключена → нет.
  3. Режим по умолчанию + фильтры (по словам в названии, времени, дням недели).
- **Одна запись за раз на слот.** Параллельно — до нескольких встреч, каждая в
  своей изоляции; сверх лимита — ждут очереди.
- **Бот не заходит в уже прошедшую встречу** (защита от «догоняющих» записей после
  перезапуска).
- **Наружу — только по явному выбору.** Облако для записей и облачный LLM
  включаются пользователем осознанно.

## 8. Метрики успеха (KPI)

| Метрика | Что показывает | Целевой ориентир |
|---|---|---|
| Доля встреч с готовым протоколом | покрытие автоматизацией | > 90% запланированных |
| Время от конца встречи до протокола | скорость конвейера | минуты, не часы |
| Точность имён ответственных | польза протокола | имена берутся с видео → «почти без ошибок» |
| Доля ручных вмешательств | зрелость автоматики | стремится к нулю |
| Аптайм сервиса | надёжность 24/7 | максимально близко к 100% |

## 9. Риски и как они снижены

| Риск | Последствие | Снижение |
|---|---|---|
| Телемост меняет вёрстку / требует вход / капчу | бот не зайдёт | списки селекторов-кандидатов, скриншот при ошибке, **ручной фолбэк** (залить файл), подробные логи |
| Нестабильная сеть к Weeek | бот «не видит» встречи | ретраи с бэкофом, принудительный коннекшн-клоуз, форс-опрос кнопкой |
| Нет видеокарты / слабый сервер | медленное распознавание | CPU-режим, int8, один воркер — предсказуемо по памяти |
| Утечка данных | репутационный/юридический ущерб | локальная обработка, шифрование секретов, изоляция по пользователям |
| Исчерпание лимитов облачного ИИ | протокол не соберётся | несколько ключей на провайдера + **авто-ротация** при лимите |
| Потеря настроек при рестарте | бот «забудет» доступы | настройки/токены **на диске** (зашифрованы), переживают перезапуск |

---

## 10. Итог одним абзацем

Сервис берёт на себя всю рутину вокруг встреч: сам записывает, распознаёт, понимает
кто говорил, пишет протокол и раскладывает результаты. Бизнес получает **экономию
времени, прозрачность решений и сохранность знаний** — при этом данные остаются
под контролем компании. Дальше по деталям: **[Системный анализ](СИСТЕМНЫЙ-АНАЛИЗ.md)**
и **[Функционал](ФУНКЦИОНАЛ.md)**.
