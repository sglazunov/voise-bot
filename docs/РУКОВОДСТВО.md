# Руководство пользователя — Voice Transcriber

Локальный сервис для **распознавания речи**, **сборки протоколов встреч** и
**автоматической записи встреч в Телемосте** (по задачам из Weeek).

Всё работает на вашем компьютере/сервере: аудио и видео никуда не уходят, кроме
тех случаев, когда вы сами выбираете облако для хранения записей или внешний
LLM-движок для протокола.

## 1. Что умеет приложение

- **Распознавание речи** из аудио и видео (до ~2 ГБ): получаете текст в форматах
  TXT, SRT (субтитры с таймкодами), JSON.
- **Точность под ваши данные**: подсказка имён/терминов и глоссарий замен, выбор
  качества модели Whisper.
- **«Кто говорил»** (диаризация) — опционально.
- **Распознавание текста с экрана** (OCR) — слайды, код, документы, показанные на видео.
- **Протокол встречи**: ИИ собирает описание, главные мысли, решения, задачи с
  ответственными — и выгружает в **Word (.docx)**. Можно сравнить несколько движков.
- **Автоматизация**: бот сам заходит на встречу в Телемосте, записывает её,
  выгружает в облако и прогоняет через распознавание + протокол. Расписание берётся
  из задач Weeek.

Две страницы:
- **`/`** — ручная работа: загрузить файл → распознать → протокол.
- **`/automation`** — настройка и управление автоматикой.

## 2. Установка и запуск

### Требования
- **Linux** (Ubuntu 22.04+ или любой с Docker), 4+ ГБ ОЗУ (комфортно 8–16 ГБ).
- **Docker** + **Docker Compose v2**.
- Для распознавания дополнительно ничего не нужно — это локальная библиотека
  `faster-whisper`, без интернета и без ключей. Всё остальное (OCR, ffmpeg,
  Chromium, модели) доустанавливается **само при первом запуске**.

### Быстрый старт
1. Скопируйте `.env` и при желании поправьте параметры.
2. Запустите **`docker compose up -d --build`**.
3. Откройте в браузере **http://localhost:8000** и зарегистрируйте первого
   пользователя — он станет администратором.

> Сервер по умолчанию слушает порт **8000**. Чтобы открыть доступ другим
> в локальной сети — запускайте с `--host 0.0.0.0` и заходите по IP компьютера.

## 3. Распознавание речи

На главной странице (`/`) выберите режим **«Распознавание»**.

1. **Загрузите файл** (перетащите или выберите). Поддерживаются mp3, wav, m4a,
   ogg, opus, flac, aac, mp4, mkv, webm, mov и др.
2. **Язык** — по умолчанию русский.
3. **Качество модели** (точность ↔ скорость/память):
   - `small` — быстро, экономно;
   - `medium` — баланс (по умолчанию);
   - `large-v3` — максимум качества, медленнее и требует больше ОЗУ;
   - `large-v3-turbo` — почти как large-v3, но быстрее.
   При выборе показывается ориентир по расходу оперативной памяти.
4. Нажмите **«▶ Распознать»**. Файл ждёт этой кнопки и раньше не отправляется —
   поэтому настройки выше можно поменять уже после выбора файла. Ошиблись
   файлом — «Убрать файл».
5. Во вкладке **«Расшифровка»** текст появляется **вживую**, по мере
   распознавания. Прокрутка «липкая»: пока вы внизу, она следует за новым
   текстом; отлистали назад читать — не дёргает обратно.
6. Кнопка **«■ Стоп»** прерывает работу. Часовая запись на `medium` считается
   около часа, поэтому ошибочно запущенную задачу лучше остановить, а не ждать.
   Уже распознанная часть сохранится.
7. Скачайте результат: **TXT / SRT / JSON**.

### История и календарь
Прошлые встречи — в блоке **«История»**, там же поиск по всем расшифровкам и
протоколам команды.

Кнопка **календаря** открывает выбор месяца, года и дня: дни со встречами
подсвечены, пустые не нажимаются. Выбрали день — список показывает только его,
«Показать все встречи» сбрасывает фильтр. Открыв встречу, можно читать протокол
и **задавать по нему вопросы**.

> ⚠️ Насколько глубоко видна история, задаёт `VTX_RETENTION_HOURS` в `.env`.
> По умолчанию **24 часа** — календарь покажет только вчера и сегодня. Чтобы
> протоколы копились, поднимите значение (например `2160` — это 90 дней).
> Места это почти не занимает: тексты и Word-документы небольшие, а тяжёлые
> записи встреч удаляются сразу после выгрузки в облако.

### Повышение точности (имена, термины)
- **Подсказка имён/терминов** — впишите фамилии, названия модулей, теги: модель
  будет писать их правильно (`initial_prompt`).
- **Глоссарий замен** — построчно `неправильно=правильно` (например `вика=Weeek`):
  применяется к готовому тексту, целые слова, без учёта регистра.

### «Кто говорил» (диаризация) — опционально
Включается галочкой. Требует:
- библиотеку `pyannote.audio` (ставится отдельно, нужна память),
- бесплатный **HF-токен** (HuggingFace) — поле для вставки появляется при включении.
Если чего-то не хватает — подсказки в интерфейсе объяснят, что доустановить.

### Текст с экрана (OCR)
Галочка «Распознавать текст с экрана» — для видео. Снимает кадры и распознаёт
показанные слайды/код/документы. Использует **Tesseract OCR** (+ русский язык) —
он уже есть в образе и ставится автоматически (`apt install tesseract-ocr tesseract-ocr-rus`).

## 4. Протокол встречи (ИИ)

Переключите режим в **«Протокол встречи»** (или после распознавания нажмите
**«Сделать протокол»**).

### Движки (на выбор)
| Движок | Тип | Что нужно |
|---|---|---|
| **NVIDIA NIM** (DeepSeek) | бесплатно, облако | ключ `nvapi-…` с build.nvidia.com — **рекомендуется** |
| **Ollama** (локально) | бесплатно, оффлайн | установить Ollama (предложит само) |
| **Gemini** | по ключу | ключ Google AI Studio — надёжный запасной |
| **Groq** | бесплатно, облако | API-ключ console.groq.com — для протоколов слабее прочих |
| **YandexGPT** | по ключу | API-ключ + folder id (Yandex Cloud) |
| **GigaChat** | по ключу | Authorization-ключ (Sber) |
| **Claude** | платно | ANTHROPIC_API_KEY |

После подключения ключа NVIDIA нажмите **«Проверить модели»**. Каталог NVIDIA
показывает около шестидесяти моделей, но аккаунту выдана только часть — проверка
перебирает их и оставляет в списке те, что реально отвечают. Без неё можно
выбрать модель, которая ответит «Not found for account» уже после встречи.

«Авто» выбирает доступный движок, предпочитая бесплатные/локальные. Ключи можно
ввести прямо в интерфейсе (кнопка подключения у движка).

### Что в протоколе
Описание встречи, разбор по темам, главные мысли, выводы, **принятые решения**,
**выполненные задачи** и **задачи к выполнению** — с **ответственными**.
Результат — **Word-файл**. Для длинных встреч текст обрабатывается по частям,
чтобы ничего не потерялось.

**Задачи разделены на два блока.** В основную таблицу попадают только те, для
которых нашлась дословная цитата из расшифровки — под каждой видно основание с
таймкодом. Остальное уходит в раздел **«Требуют проверки»**: ИИ сформулировал
их по смыслу обсуждения, но подтверждения в тексте нет. Так основной список
остаётся доверенным, а спорное не теряется.

Ответственный ставится, **только когда человек назван вслух** — сам взял задачу
или ему её поручили. Просто участие в обсуждении ответственным не делает; если
не назвали, стоит «—». Это осознанно: ложный ответственный хуже пустого.

**Пустые разделы не показываются.** Если тема свелась к пересказу собственного
заголовка, она сначала переписывается заново по расшифровке, и только если и
тогда сказать нечего — удаляется: значит тему лишь упомянули.

### Настройка промпта
- **Инструкция для ИИ** — дополнительные пожелания к протоколу.
- **Экспертный режим** — полная замена промпта (с кнопкой «сбросить к стандартному»).

### Полезное
- **Пауза/Отмена** работают и во время сборки протокола.
- **Повторить другим движком** — соберёт протокол заново, не переслушивая аудио;
  для каждого движка сохраняется отдельный Word-файл (удобно сравнивать).

### Как сделать протокол точнее ваших заметок

- **Пишите заметки со встречи** — это самый достоверный источник. Во время
  встречи: кнопка **«Live»** на карточке (сверху — живая расшифровка, снизу —
  ваши заметки). После встречи: кнопка-блокнот на карточке или блок «Заметки со
  встречи» в деталях задания → **«Сохранить и пересобрать»**. Протокол строится
  на заметках как на скелете; при противоречии с расшифровкой приоритет у них.
- **Выбирайте тип встречи** (пресет): планёрка — акцент на задачи/статусы/
  блокеры; обсуждение/дизайн — варианты и аргументы; демо — что показали и
  какие доработки; 1:1 — договорённости. В Планировщике режим «Авто» подбирает
  пресет по названию встречи сам.
- **Смотрите на пометки «⚠ проверьте»**: каждый пункт задач/решений система
  подтверждает дословной цитатой из расшифровки (основание раскрывается по
  клику, в Word — сноской). Пункт без подтверждения — серым с пометкой;
  ответственный никогда не появляется без фразы-основания («я возьму»,
  «Кирилл, сделай»). Отключается тумблером «Строгая проверка» в Планировщике.
- **Правьте прямо в интерфейсе**: кнопка **«Редактировать»** у готового
  протокола — резюме, темы, решения и задачи правятся на месте, Word
  пересобирается. У каждой темы есть кнопка **перегенерации** — ИИ перепишет
  только её, не трогая остальное.
- **Спрашивайте по встрече**: поле «Спросить по встрече» под протоколом —
  вопрос вида «что решили по тегам?» получит ответ с таймкодами; если тема
  не обсуждалась, система так и скажет.
- **Ищите по всем встречам**: строка поиска над историей — полнотекстовый
  поиск по расшифровкам и протоколам команды (работает русская морфология).
- **Неуверенные места расшифровки** подчёркнуты пунктиром — там стоит
  проверить имена и цифры. Добавьте частые ошибки в **глоссарий**
  («услышал=правильно») и имена/проекты в **Контекст для ИИ** — система сама
  подсказывает их распознаванию.
- **Участники протокола** — строго те, кто был в окне Телемоста (по подписям
  плиток). Люди, о которых лишь говорили, в список участников не попадают.
- **Несколько встреч подряд**: записи идут параллельно (до 4), а распознавание —
  по очереди, по одной (так быстрее на одном сервере). Пока встреча ждёт
  очереди, её live-текст уже доступен; о готовности протокола придёт
  уведомление в Telegram, если настроить бота в Планировщике.

## 5. Автоматизация встреч

Страница **`/automation`**. Полный цикл: **Weeek → бот записывает Телемост →
облако → распознавание → протокол → комментарий в Weeek**. Рассчитана на сервер,
который работает постоянно (24/7).

> **Важно про Телемост.** Публичного API для ботов у Телемоста нет, поэтому запись
> делает **бот-участник**: браузер заходит на встречу и пишет звук+экран. Это самая
> чувствительная часть — нужна разовая настройка на машине (см. ниже), а у записи
> всегда есть ручной фолбэк (кнопка «Стоп») и логи.

Настройки разбиты на 4 карточки.

### 5.1. Weeek
- **API-токен** — персональный ключ из **настроек воркспейса** Weeek (не cookie из
  браузера!). Хранится на сервере, доступ у бота постоянный. Один токен «видит»
  **все проекты** воркспейса.
- **Сбросить токен** — кнопка очищает сохранённый токен (после подтверждения),
  когда нужно сменить его или переключиться на другой воркспейс.
- **ID проекта** — необязательно, чтобы ограничить запись **одним проектом**. Пусто
  = записываются встречи из всех проектов. Кнопка **«Мои проекты»** покажет список
  ваших проектов с их ID — нажмите «Выбрать», и ID подставится автоматически.
- **Часовой пояс** — по умолчанию `Europe/Moscow` (для встреч, где время указано
  локально).
- Кнопка **«Показать ближайшие встречи»** — проверка связи и просмотр того, что бот
  видит; здесь же выбирается, какие встречи записывать (см. 5.4).

**Как завести встречу в Weeek, чтобы бот её записал:**
1. В задаче добавьте **кастом-поле со ссылкой** на Телемост (тип «ссылка»). Бот
   найдёт именно Телемост-ссылку, даже если в задаче есть и другие ссылки.
2. Укажите **дату и время** встречи — по ним бот поймёт, когда заходить.

### 5.2. Куда сохранять запись (облако)
Выберите облако и заполните доступы. Секреты хранятся на сервере.
- **Локально на диск** — папка на сервере (по умолчанию `data/recordings`).
- **Яндекс Диск** — нужен **OAuth-токен** со scope `cloud_api:disk.write` + папка.
  > **Важно:** ClientID и Client secret вашего приложения Яндекса — это **не токен**,
  > их в поле вставлять нельзя (будет ошибка 401). Токен получается отдельно:
  > впишите **ClientID** и нажмите **«Получить токен»** — откроется страница Яндекса,
  > разрешите доступ, и на странице `oauth.yandex.ru/verification_code` появится сам
  > токен. Скопируйте его в поле «OAuth-токен Я.Диска» и нажмите «Сохранить».
  > (Токен живёт ~год; при ошибке 401 позже — получите новый тем же способом.)
- **Google Drive** — `client_id`, `client_secret`, `refresh_token` (OAuth-клиент
  типа Desktop, scope `drive.file`) + id папки.
- **«Тест загрузки»** — заливает крошечный файл, чтобы проверить доступ.

### 5.3. Бот-рекордер
Запись делается **захватом экрана** (ffmpeg): бот-браузер заходит на встречу
**с выключенными микрофоном и камерой** (никакого звука от бота в встречу не идёт —
он только пишет), окно открывается **на весь экран**, и ffmpeg пишет видео + звук
встречи в один файл. Ограничения встроенной записи Телемоста (30 минут, только для
организатора) на это не распространяются.

- **Режим входа:**
  - **Гость** — заходит по ссылке, вписывает имя бота (по умолчанию «Протокол-бот»);
  - **Авторизованный** — использует профиль браузера с входом в Яндекс
    (кнопка **«Войти в Яндекс»** — один раз залогиниться в открывшемся окне;
    **«Проверить вход»** покажет, активна ли сессия).
- **ffmpeg** — путь к ffmpeg (по умолчанию `ffmpeg` из PATH).
- **Аудио-устройство встречи** — то, что пишет звук участников (loopback /
  виртуальный кабель, напр. «CABLE Output»). Список — кнопкой «Обновить список устройств».
- **«Проверить звук»** — записывает 3 секунды с выбранного устройства и показывает,
  идёт ли звук («✓ звук есть» / «✗ тишина»). Позволяет убедиться, что звук встречи
  дойдёт до записи, **не записывая** целую встречу (см. настройку звука в 5.5).
- **Записывать экран** — для распознавания того, что показывают.
- **Скрытый браузер (headless)** — без видимого окна (для захвата экрана окно нужно
  видимое, поэтому при записи браузер открыт).

**Когда останавливается запись** (по первому событию):
- вы нажали **«Остановить запись»** (самый надёжный способ);
- сработал **потолок по времени** (`max_meeting_min`);
- бот **выпал** из звонка;
- в комнате осталось **≤ N человек** дольше заданного времени
  (`min_participants` + «…дольше, сек.»). Истончение считается только **после**
  того, как на встрече реально были люди — ранний вход запись не завершит.

> Пример под «одна и та же ссылка, после встречи остаются поболтать»: поставьте
> порог, скажем, 3 человека — и «хвост» из пары оставшихся в запись не попадёт.

- **«Тест записи»** — зайти по ссылке и записать N секунд; вернёт путь к файлу и логи.

### 5.4. Планировщик
- **Главный выключатель** «Включить автоматическую запись встреч».
- **Что делать после записи** (независимые галочки):
  - **Распознать речь** (транскрипция);
  - **Собрать протокол** (Word) — требует распознавания;
  - **Распознать текст с экрана** (OCR) — требует распознавания.
  Запись и выгрузка в облако делаются **всегда**; остальное — по вашему выбору.
- **Опрос Weeek** (как часто перечитывать задачи), **за сколько минут до старта**
  заходить, **движок протокола**, **комментарий в Weeek** со ссылкой на запись.
- **Статус** — состояние потока, идёт ли запись, список встреч со статусами
  (запланирована / запись / выгрузка / распознавание / готово / пропущено / ошибка).
  Кнопки **«Записать сейчас»** и **«Остановить запись»**.

**Какие встречи записывать (фильтры и точечный выбор).** В блоке «🎯 Какие встречи
записывать»:
- **Режим по умолчанию:** «Записывать все» (пишутся все встречи, кроме отключённых
  вручную) либо «Только выбранные» (пишутся только включённые вручную).
- **Фильтры** по времени, дням недели и словам в названии (включить/исключить).
  Пусто во всех полях = записывать все.
- **Точечный выбор по каждой встрече:** в списке «Показать ближайшие встречи» у
  каждой встречи есть переключатель **по умолчанию / ✅ записывать / 🚫 не
  записывать**. Ручной выбор **главнее** фильтров по словам/времени.

> **Бот не заходит на встречи, начавшиеся до запуска приложения.** После старта он
> записывает только встречи, которые начинаются, пока приложение уже работает —
> старые/прошедшие помечаются «пропущено» и в них бот не врывается. Любую встречу
> (в т.ч. прошедшую) можно записать вручную кнопкой «Записать сейчас».

> **Двойного захода не будет.** Запись на машине эксклюзивна: одновременно идёт
> только одна (защита от двух ботов в одном звонке — даже если запущено два
> экземпляра приложения).

### 5.5. Что нужно один раз настроить на машине
Многие из этих шагов можно выполнить **прямо из интерфейса** — в карточках есть
кнопки установки недостающих компонентов (Playwright, ffmpeg, виртуальный аудио-кабель,
модели распознавания, Ollama).

1. **Браузер для бота:** `pip install playwright` → `playwright install chromium`
   (или кнопка установки Playwright в интерфейсе).
2. **ffmpeg** в PATH (`ffmpeg -version`) — или кнопка «Установить ffmpeg».
3. **Звук встречи в запись.** Настраивать нечего: браузер бота играет звонок
   в виртуальный «динамик» PulseAudio (`meet0`…`meetN` — по одному на слот
   записи), а ffmpeg пишет его монитор (`meet0.monitor`). Sink'и создаются при
   старте контейнера с `VTX_RECORDER_ENABLED=1`. Кнопка **«Проверить звук»**
   покажет, идёт ли сигнал (во время реальной встречи).
4. Прогнать **«Тест записи»** на реальной ссылке. Вёрстка Телемоста меняется, и
   селекторы входа, возможно, потребуют подстройки (при неудаче бот сохраняет
   скриншот и логи).

### Надёжность записи и уведомления

- **Запись не теряется при сбое**: файл пишется в устойчивом формате
  (fragmented MP4) — даже жёсткое падение сервиса посреди встречи оставляет
  читаемую запись до последней секунды. После рестарта сервис сам находит
  оборванные записи и дообрабатывает их: облако → ссылка в Weeek →
  расшифровка → протокол. Руками ничего делать не нужно.
- **Сторож звука**: во время записи уровень звука замеряется каждые 30 секунд;
  2 минуты тишины подряд → «⚠ НЕТ ЗВУКА» в живом логе карточки и уведомление
  в Telegram — немая запись обнаруживается сразу, а не после встречи.
- **Telegram-уведомления**: в Планировщике укажите токен бота (@BotFather) и
  chat_id (боту @userinfobot перешлите любое сообщение из чата) — прилетят
  «📄 протокол готов» со ссылкой, «⚠ протокол не собрался» и «⚠ нет звука».
  Кнопка «Проверить отправку» шлёт тестовое сообщение.
- **Деплой во время встречи**: даже если сервис перезапустить в момент записи
  или обработки, ссылки на видео/протокол доставятся после рестарта —
  незавершённые встречи подхватываются автоматически.

## 6. Требования к ресурсам

| Модель Whisper | Память (≈) | Комментарий |
|---|---|---|
| small | ~1 ГБ | быстро |
| medium | ~1.5 ГБ | по умолчанию, хороший баланс |
| large-v3 / turbo | ~3 ГБ | максимум качества |

- Первый запуск крупной модели **скачивает её** (large-v3 ~3 ГБ) — поэтому
  «Загрузка модели…» в первый раз может идти несколько минут.
- Локальный движок протокола (Ollama, qwen2.5:7b) — ещё ~5 ГБ ОЗУ.
- Диаризация — заметно увеличивает расход памяти.

## 7. Приватность и хранение данных

- Распознавание и OCR — **полностью локально**, без интернета.
- Протокол уходит во внешний LLM, **только** если вы выбрали облачный движок
  (NVIDIA/Gemini/Groq/Yandex/GigaChat/Claude). Ollama — локально.
- Запись уходит в облако, **только** если вы выбрали Я.Диск/Google Drive
  (вариант «локально» никуда не отправляет).
- **Токены автоматизации** хранятся на сервере в `data/automation.json`
  (права 0600). Держите папку `data/` приватной.
- Результаты по умолчанию хранятся ограниченное время и затем автоудаляются.

## 8. Решение проблем

**«Загрузка модели…» висит несколько минут.** Первый запуск крупной модели качает
её (до ~3 ГБ). Дальше будет быстро.

**Распознавание идёт долго и кажется, что зависло.** Сначала посмотрите на
вкладку «Расшифровка»: если текст прибавляется — работа идёт. На `medium`
часовая запись считается около часа, а включённые «Спикеры (видео)» и «OCR
экрана» добавляют ещё. Убедиться, что процесс жив, можно и с сервера:
`docker stats --no-stream linux-voise` — загрузка процессора около 300%
означает, что он считает; около нуля — встал.

**Запись получилась без звука.** В логе ffmpeg строки про `probesize` и
`not enough frames` относятся к видео и уводят в сторону — ищите ниже строки
про PulseAudio. Частая причина: команду `pactl` выполнили внутри контейнера от
root, и служебный каталог достался root, а приложение работает под другим
пользователем. Проверять звук нужно так:
`docker compose exec -u app app sh -c 'pactl list short sources | grep meet'`
(с флагом `-u app`), а чинится это перезапуском: `docker compose up -d`.

**Ошибки установки/запуска про ctranslate2 / onnxruntime.** Нужен **Python 3.12**
(не 3.14) и **Microsoft Visual C++ Redistributable** (x64).

**Кириллица в путях.** Избегайте кириллицы в системных путях для внешних утилит —
приложение пишет файлы в UTF-8, но сторонние бинарники иногда спотыкаются.

**Провайдер протокола не подключается:**
- *Groq 401/429* — проверьте ключ; на бесплатном тарифе бывают лимиты (подождите/повторите).
- *YandexGPT* — нужен **folder id** (вид `b1g…`, не `aje…`), роль `ai.languageModels.user`
  и привязанный платёжный аккаунт; ключ со scope `yc.ai.languageModels.execute`.
- *GigaChat 401* — нужен именно **Authorization-ключ** (base64), не Client ID/Secret.
- *NVIDIA «Not found for account»* — ключ рабочий, но эта модель аккаунту не
  выдана. Каталог показывает всё опубликованное, права у́же. Нажмите
  «Проверить модели» и выберите из проверенного списка.

**Протокол собрал не тот движок, который выбирали.** В шапке документа есть
строка `Движок: <провайдер> · <модель>` — это тот, кто реально ответил. Если под
ней стоит «Выбранный движок не ответил…», там же написана причина (лимит,
таймаут, недоступная модель). Выбранный движок мог не ответить, и работу принял
следующий по списку.

**Скачался протокол предыдущей версии.** На кнопке написано, чей это документ
(«Word · nvidia»), а при нескольких версиях рядом появляется выбор движка.
Пересборка пишет отдельный файл на каждый движок — старый не затирается.

**Бот записал пустую комнату несколько часов.** Признаки «все вышли» читаются из
вёрстки Телемоста, и когда она их не отдаёт, запись шла до предела длины. Теперь
есть выход по тишине: `VTX_END_ON_SILENCE_SEC=600` — десять минут тишины после
начавшегося разговора завершают запись.
- *Gemini 429* — на бесплатном тарифе без биллинга квоты может не быть.

**Weeek: «отклонил токен».** Вы вставили cookie из браузера, а нужен **API-токен**
из настроек воркспейса.

**Я.Диск: «отклонил токен (401)».** Скорее всего вы вставили **ClientID/Client
secret** вместо токена. Получите токен кнопкой «Получить токен» (см. 5.2); токену
нужен scope `cloud_api:disk.write`.

**«Запись сохранилась, но статус — ошибка / The read operation timed out».** Файл на
диске есть — это сетевой таймаут на шаге *после* загрузки (получение ссылки или
комментарий). Исправлено: такой таймаут больше не валит задачу, запись считается
успешной. Если видите это на старой записи — просто перезапишите/прогоните файл
через ручную загрузку.

**Бот не заходит на встречу.** Проверьте: установлен ли `playwright`
(+`playwright install chromium`); для приватных встреч — режим **«Авторизованный»**
и вход в Яндекс. При неудаче смотрите скриншот рядом с файлом записи и логи в
«Тест записи». Возможно, изменилась вёрстка Телемоста — селекторы в
`app/automation/recorder/browser.py` подстраиваются.

**Запись есть, но пустой/тихий файл.** Звук встречи не попал в PulseAudio-монитор.
Проверьте, что контейнер запущен с `VTX_RECORDER_ENABLED=1` (тогда sink'и `meet0…`
создаются при старте) и что в списке источников есть `meet0.monitor`. Нажмите
**«Проверить звук»** во время встречи — должно показать «✓ звук есть».

**Бот заходит дважды / окна Хрома открываются сами.** Исправлено: запись на машине
эксклюзивна, а после перезапуска бот не заходит в уже начавшиеся встречи. Если видите
такое — закройте лишний экземпляр приложения и обновитесь до актуальной версии.

**Время встречи сместилось на несколько часов.** Проверьте **часовой пояс** в
настройках Weeek (по умолчанию `Europe/Moscow`).

## 9. Частые вопросы

**Нужен ли интернет для распознавания?** Нет. Распознавание и OCR работают локально.

**Сохраняются ли токены после перезапуска?** Да, токены Weeek и облаков лежат на
диске — бот сохраняет доступ постоянно. (Я.Диск-OAuth со временем истекает, тогда
обновите его один раз.)

**Можно записывать только видео, без распознавания?** Да — выключите «Распознать
речь» в планировщике; в облако ляжет только видеофайл.

**Можно распознать без протокола?** Да — включите «Распознать речь», выключите
«Собрать протокол».

**Как записывать встречи только одного проекта?** Токен Weeek видит весь воркспейс;
ограничивает запись поле «ID проекта». Нажмите «Мои проекты» → «Выбрать» у нужного.
Пусто = все проекты.

**Как выбрать, на какие встречи бот заходит, а на какие нет?** В блоке «🎯 Какие
встречи записывать» выберите режим («все» или «только выбранные») и/или задайте
фильтры по словам/времени. Точечно — в списке встреч переключателем у каждой
(✅ записывать / 🚫 не записывать). Ручной выбор главнее фильтров.

**Идёт ли от бота звук в встречу?** Нет. Бот заходит с **выключенными микрофоном и
камерой** и только записывает.

**Один и тот же или разные линки на встречи?** Поддерживается и то, и другое —
ссылка берётся из задачи Weeek. Для постоянной ссылки удобно использовать порог
участников, чтобы запись завершалась, когда основная встреча закончилась.

**Где взять файлы и протоколы?** Ручные задачи — на главной странице (кнопки
скачивания). Автоматические — в выбранном облаке (запись) и среди задач
распознавания (протокол), плюс ссылка в комментарии Weeek.
