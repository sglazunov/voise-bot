# 🗂 Полный функционал

Каталог всех возможностей системы. По каждому пункту: **что это**, **как включить**
и **что на выходе**. Технические детали — в **[Бэкенд](БЕКЕНД.md)**, пошаговые
истории — в **[Пользовательских сценариях](ПОЛЬЗОВАТЕЛЬСКИЕ-СЦЕНАРИИ.md)**.

Условные обозначения: 🟢 всегда · 🔧 включается настройкой/галочкой · 🧪 опционально
(нужны зависимости/ключ).

## A. Распознавание речи (ASR)

| Возможность | Тип | Описание |
|---|---|---|
| Загрузка аудио/видео | 🟢 | Файл загружается на странице `/`. Видео поддерживаются напрямую (звук извлекается сам). |
| Распознавание в текст | 🟢 | Движок **faster-whisper** локально превращает речь в текст с тайм-кодами. |
| Живой прогресс | 🟢 | Текст и процент готовности видны **в реальном времени** по мере распознавания. |
| Пауза / возобновление / отмена | 🟢 | Задачу можно приостановить и продолжить или отменить; проверяется между сегментами. |
| Выбор модели | 🔧 | Баланс скорость/точность (small … large-v3-turbo). |
| Подсказка имён/терминов | 🔧 | Список известных имён и терминов повышает точность их написания. |
| Глоссарий замен | 🔧 | Правила «как слышится → правильно» (напр. «кафка = Kafka») применяются к тексту. |
| Экспорт TXT / SRT / JSON | 🟢 | Готовый текст, субтитры и машинный JSON с сегментами доступны для скачивания. |

---

| **Авто-подсказка имён и терминов** | 🟢 | Whisper получает подсказку (~224 токена): имена людей из AI-контекста команды и с плиток прошлых видео (с фильтром «похоже на имя»), названия проектов, правильные написания из глоссария — знакомые имена пишутся как надо, а не «по слуху». |
| **Анти-галлюцинации** | 🟢 | «Выдуманные» фразы на тишине (высокая вероятность тишины + низкая уверенность декодера) отбрасываются; зацикленные повторы (≥3 одинаковых сегмента подряд) схлопываются. Пороги настраиваются в env. |
| **Подсветка неуверенных мест** | 🟢 | В просмотре расшифровки сегменты с низкой уверенностью Whisper — серым с пунктирным подчёркиванием: сразу видно, где проверять имена и цифры. |
| Очередь распознавания | 🟢 | Записи бот делает параллельно (до 4), а распознаёт строго ПО ОДНОЙ (одна модель в памяти; параллельная инференция на CPU замедлила бы обе). Статусы «в очереди»/прогресс — на карточках. |

## B. Кто говорил (спикеры)

| Возможность | Тип | Описание |
|---|---|---|
| **Определение говорящего по видео** | 🧪 | С кадров Телемоста читается **зелёная подсветка активного участника** и его **имя** (OCR), реплики подписываются реальными именами. Для бота — включено по умолчанию. |
| Диаризация по звуку | 🧪 | Опциональное разделение на «Спикер 1/2…» через pyannote (нужен HF-токен и память). |
| Тонкая настройка распознавания подсветки | 🔧 | Пороги цвета/детекции — через `VTX_SPEAKER_*`; есть `debug_report()` для калибровки по реальной записи. |

> Почему это важно: в тексте расшифровки **нет** пометок «кто сказал». Раньше ИИ
> угадывал ответственных и ошибался. Теперь имена берутся **прямо с картинки** —
> и ответственные в протоколе проставляются точно.

## C. Протокол встречи (ИИ)

| Возможность | Тип | Описание |
|---|---|---|
| Сборка протокола | 🔧 | ИИ по тексту составляет структурированный протокол. |
| Что попадает в протокол | 🟢 | Участники, краткое содержание, **подробный разбор по темам**, ключевые мысли, выводы, **решения**, выполненные задачи, **задачи и ответственные**, мелкие задачи. |
| Понятность «для того, кого не было» | 🟢 | Промпт требует писать простым языком, с контекстом в начале каждой темы, самодостаточно (10–12 предложений на тему). |
| Достоверные ответственные | 🟢 | Owner ставится **только** при явном «я возьму»/поручении по имени; метки-имена из видео считаются достоверными; иначе — «—» (лучше пусто, чем ошибочно). |
| **Постоянный контекст для ИИ** | 🟢 | Вкладка «Контекст для ИИ»: **общий блок** (кто есть кто, роли, термины, суть проектов) подмешивается в **каждый** протокол, **контекст проекта** — автоматически, когда название проекта встречается в теме встречи или имени файла. ИИ использует это как справку и **не выдумывает** факты встречи. Решает проблему «протокол путает роли и названия». Правки не потеряются: при уходе со страницы без сохранения — предупреждение. |
| Длинные встречи (map-reduce) | 🟢 | Длинный текст режется на части с перекрытием: сначала заметки по частям, потом сведение в единый протокол — ничего не теряется. |
| Экспорт в Word (.docx) | 🟢 | Готовый документ по каждому движку, скачивается из интерфейса. |
| Выгрузка расшифровки | 🟢 | Выпадающий список формата: **TXT / SRT / JSON** + кнопка «Скачать». |
| Видимый ход сборки | 🟢 | На «Распознавании» видно живую стадию: сколько фрагментов распознано, а при сборке протокола — текущий этап и сколько символов уже пришло от ИИ. |
| Понятные ошибки | 🟢 | Вместо Python-трейсбека — короткое сообщение: движок перегружен (503), лимит (429), ключ отклонён, модель недоступна, таймаут. Полный трейсбек уходит в лог сервера. |
| Экспертный режим (правка промпта) | 🔧 | Полностью редактируемый промпт для тонкой настройки под себя. |
| Повторный анализ (reanalyze) | 🔧 | Пере-собрать протокол по уже готовому тексту другим движком — без повторного распознавания. |

### Движки протокола (LLM)

| Движок | Где считает | Ключ |
|---|---|---|
| **Ollama** | локально/оффлайн | не нужен |
| **Groq** (Llama) | облако, бесплатный тариф | нужен ключ |
| **Google Gemini** | облако | нужен ключ |
| **YandexGPT** | облако | ключ + folder id |
| **GigaChat / Sber** | облако | ключ (authorization) |
| **Anthropic Claude** | облако, платно | нужен ключ |

| Возможность движков | Тип | Описание |
|---|---|---|
| **Вкладка «Нейросети»** | 🟢 | Отдельный экран управления: ввод API-ключа провайдера (с проверкой перед сохранением), список своих ключей в маске с удалением, отключение провайдера, статус Ollama и список доступных моделей. |
| Выбор нейросети и модели | 🔧 | Провайдер + его модель выбираются как «движок протокола»: на «Распознавании» (для загруженного файла) и в «Планировщике» (для автоматики). |
| Несколько ключей на провайдера | 🔧 | Можно добавить несколько ключей (напр. для Groq). |
| **Авто-ротация ключей при лимите** | 🟢 | При ошибке лимита (429) сервис сам переключается на следующий ключ — генерация не прерывается. |
| **Fallback между провайдерами** | 🟢 | Если выбранный движок недоступен (5xx, сеть, все ключи в лимите), запрос автоматически уходит следующему настроенному провайдеру (бесплатные/локальные — в приоритете): упавшая Gemini не срывает протокол, его доделает Groq или Ollama. В протоколе указывается, кто реально его собрал. |
| Ключи в аккаунте (один раз) | 🔧 | Ключи хранятся зашифрованными; в команде — общие (под ключом админа команды). |

### Точность и доверие (наведение порядка в протоколе)

| Возможность | Тип | Описание |
|---|---|---|
| **Хронология и структура (map-reduce v2)** | 🟢 | Анализ идёт по расшифровке С ТАЙМКОДАМИ; заметки по частям — структурный JSON (темы/решения/задачи с таймкодами и цитатами), дубли из зон перекрытия склеиваются механически, порядок тем в протоколе = ход встречи. Слишком длинные встречи сводятся иерархически — конец встречи не теряется и не обрезается молча. |
| **Валидный JSON всегда** | 🟢 | Ollama получает схему как грамматику структурного вывода (битый ответ невозможен); облачные ответы валидируются со схемой и одним повтором. |
| **Проверка по цитатам (grounding)** | 🟢 | Каждый пункт задач/решений должен получить ДОСЛОВНУЮ цитату-основание с таймкодом (проверяется механически — перефраз не считается). Неподтверждённые пункты — серым с «⚠ проверьте» (в UI и Word); основание раскрывается по клику/в сноске. Ответственный не появляется без фразы-основания. Тумблер «Строгая проверка» в Планировщике (вкл). |
| **Заметки участника** | 🟢 | Свои живые заметки — самый достоверный источник: протокол строится на них как на скелете, при противоречии с расшифровкой приоритет у заметок. Ввод: во время встречи (кнопка «Live» на карточке), после встречи (кнопка-блокнот / блок в деталях задания + «Пересобрать»), при загрузке файла. |
| **Участники — строго из окна Телемоста** | 🟢 | Список участников протокола механически заменяется на подписи плиток звонка: человек, о котором лишь ГОВОРИЛИ, в «Участники» не попадает. Роли из разговора сохраняются. Без видео — по тексту, по строгим правилам. |
| **Пресеты под тип встречи** | 🟢 | Планёрка (задачи/статусы/блокеры), обсуждение/дизайн (варианты, аргументы, «Открыто:»), демо (что показали, вопросы, доработки), 1:1 (договорённости, без пересказа личного), универсальный. «Авто» подбирает по названию встречи; свои пресеты — per-team через API. |
| **Редактор протокола** | 🟢 | Кнопка «Редактировать»: резюме, темы, решения, задачи («задача — ответственный») правятся прямо в UI; Word пересобирается. Правки человека доверенные — пометки проверки снимаются. |
| **Перегенерация одного раздела** | 🟢 | Кнопка у темы в редакторе: LLM переписывает ТОЛЬКО эту тему по расшифровке, остальной протокол не трогается. |
| **Чат по встрече** | 🟢 | «Спросить по встрече» под протоколом: вопрос («что решили по тегам?») → ответ с таймкодами из расшифровки; если не обсуждалось — честно скажет. |
| **Эталонный тест качества** | 🟢 | `tests/eval/`: реальные встречи с выверенными эталонами; метрики recall/precision задач, точность ответственных, полнота тем; история прогонов в history.jsonl; пороги релиза recall ≥ 0.90, owner ≥ 0.95. |

## E. Автоматизация встреч (Weeek → Телемост → облако → протокол)

| Возможность | Тип | Описание |
|---|---|---|
| Опрос Weeek | 🔧 | Планировщик периодически ищет в Weeek встречи со ссылкой на Телемост и временем. |
| Бот-запись Телемоста | 🔧 | В назначенное время браузер заходит гостем (микрофон/камера выкл.) и пишет экран+звук. |
| Автоостановка записи | 🟢 | Останавливается, когда все вышли / по порогу тишины/участников / по потолку длительности. |
| Ручная остановка | 🟢 | Кнопка «Остановить запись». |
| Запуск «Сейчас» | 🔧 | Записать известную встречу немедленно, не дожидаясь времени. |
| **Принудительный опрос Weeek** | 🟢 | Кнопка «Обновить статус» делает немедленный опрос — новые встречи/статусы подтягиваются сразу. |
| Выгрузка в облако | 🔧 | Запись уходит в Яндекс.Диск / Google Drive / локальный диск; **протоколы — в отдельную папку**. |
| Ссылки в Weeek | 🔧 | Ссылки на запись/протокол пишутся в кастом-поля задачи и/или комментарий. |
| **Доставка ссылок переживает рестарт** | 🟢 | Прикрепление протокола «живёт» в самой задаче распознавания: деплой/перезапуск сервиса больше не теряет ссылку — при старте сервис подхватывает незавершённые встречи и допоставляет протоколы; «Пересобрать» после сборки прикрепляет ссылку сам. Если протокол не прикрепился — в задаче Weeek появляется комментарий с причиной. |
| **Ручное прикрепление ссылок** | 🟢 | Кнопка-скрепка на карточке встречи: вставить ссылку на видео и/или протокол руками — попадут в кастом-поля задачи Weeek (или комментарием, если поля нет). Для случаев, когда автоматика не смогла (файл только у участника и т.п.). |
| **Управление записью галочкой в Weeek** | 🔧 | Чекбокс-поле «Запись встречи» в задаче: включён → писать, выключен → не заходить. |
| Фильтры «какие писать» | 🔧 | Режим по умолчанию, слова в названии (вкл/искл), окно времени, дни недели. |
| Точечный выбор встречи | 🔧 | Для каждой встречи — «записывать / не записывать» вручную (главнее фильтров). |
| Параллельная запись | 🟢 | До нескольких встреч одновременно (по умолч. 4), каждая изолирована (свой экран + аудио-синк). |
| Живые статусы + «Сегодня» | 🟢 | Вкладка «Встречи» открывается сразу на фильтре **«Сегодня»**, список обновляется без перезагрузки. |
| Ручное подключение бота | 🟢 | У пропущенных (а также пропуск/без времени/ошибка) встреч — кнопка **«Подключиться»**: бот заходит на встречу вручную. |
| Обновить из Weeek | 🟢 | Кнопка форсирует опрос Weeek немедленно (со спиннером «Обновляю…»), не дожидаясь интервала. |
| После записи — конвейер | 🔧 | Флаги «распознать речь», «собрать протокол», «OCR экрана», «определять говорящего». |
| **Live-расшифровка во время встречи** | 🟢 | Текст встречи появляется каждые ~5 минут ПРЯМО ВО ВРЕМЯ записи (кнопка «Live» на карточке): сверху растущая расшифровка, снизу — ваши заметки. После встречи сменяется финальной расшифровкой и протоколом. |
| **Запись не теряется при сбое** | 🟢 | Пишется fragmented MP4: kill -9/OOM посреди встречи оставляет читаемый файл. После рестарта сервис сам находит оборванные записи и дообрабатывает (облако → Weeek → расшифровка → протокол) — без ручных действий. |
| **Контроль звука во время записи** | 🟢 | Каждые 30 с замеряется уровень записываемого звука; 2 минуты тишины подряд → «⚠ НЕТ ЗВУКА» в живом логе карточки + уведомление в Telegram. Немая запись обнаруживается за минуты, а не после встречи. |
| **Уведомления в Telegram** | 🟢 | Бот команды (токен+chat_id в Планировщике, токен шифруется): «протокол готов» со ссылкой, «протокол не собрался», «нет звука». Кнопка «Проверить отправку». |
| **Спикеры — всегда** | 🟢 | Определение говорящих по видео (подписи плиток + подсветка активного) включено БЕЗУСЛОВНО для всех записей бота; тумблер в настройках касается только загруженных вручную файлов. Диаризация аудио-файлов — опцией сборки DIARIZATION=1 (нужно ≥8 ГБ RAM). |

## E2. Бизнес-метрики («Обзор»)

Дашборд отвечает на вопрос «что автоматизация даёт бизнесу». Фильтр периода
**7 / 30 / 90 дней**. Итог каждой встречи сохраняется отдельно и **переживает
ретеншн задач**, поэтому статистика копится вдолгую.

| Метрика | Тип | Описание |
|---|---|---|
| Встреч обработано, Часов записано | 🟢 | Объём: сколько встреч прошло через систему и сколько часов записано. |
| **Поручений зафиксировано** | 🟢 | Сколько задач ИИ вытащил из встреч — прямой практический выход. |
| Решений зафиксировано | 🟢 | Сколько решений/договорённостей закреплено. |
| **Человеко-часов встреч** | 🟢 | Длительность × число участников — сколько совокупного времени команды съели встречи. |
| Протоколов готово, Средняя встреча | 🟢 | Сколько протоколов собрано; средняя длительность встречи. |
| Надёжность обработки | 🟢 | Доля успешно обработанных (и сколько сбоев). |
| Динамика по дням | 🟢 | Столбчатый график загрузки за период. |
| **«Что съедает время»** | 🟢 | Топ регулярных встреч по суммарным часам — видно, какие созвоны обходятся дороже всего. |
| ≈ Сэкономлено на протоколах | 🔧 | **Оценка** (не замер): часы × `VTX_MINUTES_COEFF` (по умолч. 0.5 — ручное протоколирование ≈50% длительности). В интерфейсе подписано как оценка с указанием коэффициента. |

> Все метрики, кроме «сэкономлено», измерены по фактически обработанным встречам.

| Отдельная папка для протоколов | 🔧 | Протоколы (.docx) складываются отдельно от видео. |

## G. Доступ, безопасность, эксплуатация

| Возможность | Тип | Описание |
|---|---|---|
| Логин/пароль | 🟢 | Весь доступ закрыт входом; пароли — PBKDF2 (минимум 6 символов), сессии-cookie (HttpOnly, SameSite). |
| **Команды и код приглашения** | 🟢 | Регистрация **без кода** → своё окружение, вы его админ. Регистрация **с кодом** админа → входите в его команду и работаете на ЕГО настройках, токенах и API-ключах. Код виден в «Профиле», **обновляется раз в сутки**, по нему может войти сколько угодно людей. |
| Управление командой | 🟢 | В «Профиле» админ видит **список логинов** рабочего пространства и может **исключить** участника — тот мгновенно теряет доступ (сессии отзываются) и получает своё пустое окружение. |
| Удаление аккаунта | 🟢 | В «Профиле» → «Опасная зона»: полное безвозвратное удаление (логин, телефон, токены, ключи, контекст, записи) с подтверждением паролем в модальном окне. Админ с участниками удалиться не может, пока их не уберёт. |
| Админ команды ≠ админ сервера | 🟢 | Серверные операции (установки, серверный HF-токен) доступны только **основателю** — первому зарегистрированному. Владельцы команд управляют лишь своим окружением. |
| Восстановление пароля по SMS | 🟢 | Забыли пароль → на `/recover` вводится логин+телефон, приходит **одноразовый 6-значный код по SMS**, затем код+новый пароль. Код живёт минуты, сгорает после лимита попыток, все старые сессии отзываются. Шлюз — **SMS.ru** (`VTX_SMSRU_API_ID`); без ключа код пишется в лог (dev-режим). |
| Смена телефона/пароля в профиле | 🟢 | `/profile`: смена телефона (нужен текущий пароль), смена пароля (по старому паролю ИЛИ по телефону). |
| Изоляция пользователей | 🟢 | Данные, записи и токены каждого пользователя раздельны; секреты зашифрованы. |
| Настройки переживают рестарт | 🟢 | Токены/настройки автоматики — на диске (0600, зашифрованы). |
| Автоудаление старых результатов | 🟢 | Ретеншн-поток чистит устаревшие результаты. |
| **Поиск по всем встречам** | 🟢 | Строка поиска над историей распознавания: полнотекстовый поиск по расшифровкам и протоколам команды (русская морфология, фразы в кавычках, минус-слова), сниппет с подсветкой, клик открывает запись. |
| **Подсказка модели по железу** | 🟢 | Система сама рекомендует whisper-модель под RAM/CPU машины — возле выбора модели. |
| Проверки готовности в UI | 🟢 | Подсказки, чего не хватает для диаризации/OCR/спикеров/облаков/бота. |
| **Авто-настройка при первом запуске** | 🟢 | При старте система сама доустанавливает всё нужное: движок **OCR** (текст/код с экрана + имена говорящих), **ffmpeg**, **Chromium** для бота, и скачивает **все модели распознавания**. Системные пакеты ставятся через `apt`. В Docker всё уже в образе. Выключается `VTX_AUTO_SETUP=0`. |
| Установка зависимостей по требованию | 🔧 | Кнопки-фолбэк в UI, если авто-установка не смогла (нет root/sudo). Диаризация (~2.5 ГБ torch) — только по флагу `VTX_DIARIZATION=1`. |
| Health-check | 🟢 | `/healthz` для мониторинга; Docker HEALTHCHECK. |

## H. Что можно расширять (точки развития)

- Новый **LLM-движок** — класс-провайдер в `llm.py` + регистрация в `config.py`.
- Новое **облако** — модуль в `clouds/` с `readiness()`/`upload()`.
- Другой **захват A/V** — за интерфейсом `capture`.
- Другой **трекер** вместо Weeek — клиент по образцу `weeek.py`.
- Простановка **задач в трекере** из протокола (сейчас — ссылка/комментарий).

Полная карта модулей и как это дорабатывать — в **[Бэкенд](БЕКЕНД.md)**.
